# Квест-бот для университета

Telegram-бот на `pyTelegramBotAPI` (`telebot`), который ведёт студентов по
маршруту из городских точек и передаёт фото-отчёты кураторам на проверку.
Рядом лежит статический информационный сайт (`site/`) с описанием точек
трёх основных секторов.

## Сайт с описанием точек

`site/index.html`, `site/sector1.html`, `site/sector2.html`, `site/sector3.html`
— статические страницы (без сборки, без сервера) с фотографиями и описанием
мест каждого сектора. Открываются прямо из файловой системы двойным кликом
или разворачиваются на любом статическом хостинге (GitHub Pages, Netlify и
т.п.) — просто выложите содержимое `site/` вместе с папкой `pics/` рядом с ним.

Сектор 4 («дополнительно») сайта не имеет — по заданию туда попадают только
самые смелые студенты уже внутри бота, отдельная страница не нужна.

Тексты о местах я собирал через веб-поиск (Дом учёных, памятник мыши, парк
Лаврентьева, история района «Щ» и т.д. — подтверждённые факты с указанием
источников в чате). Для нескольких точек без чёткой публичной информации
(например, «Свиток») описание оставлено коротким и нейтральным, без
выдуманных подробностей — поправьте по месту, если нужно.

Если добавите в `coordinates.txt` новую точку с фотографией, положите
фото в `pics/secN/` и добавьте карточку в соответствующий `siteN.html`
по образцу уже существующих в `sector1.html`/`sector2.html`/`sector3.html`
(в каждом файле есть и карточка с фото, и карточка-плейсхолдер без фото —
берите за образец подходящую).

## Как это работает

1. Студент пишет боту `/start` и выбирает свой маршрут — последовательность
   секторов 1-2-3, которую вы называете ему очно (например, «2-1-3»).
2. Бот присылает координаты первой точки маршрута с двумя кнопками:
   **«📷 Отправить фото»** и **«🆘 Техническая поддержка»**.
3. Студент нажимает «Отправить фото» и присылает фотографию. Бот пересылает
   её куратору **того сектора, в котором сейчас находится студент**, вместе
   с кнопками **«✅ Подходит»** / **«❌ Не подходит»**.
4. Как только куратор нажимает «Подходит», бот присылает студенту
   следующую точку. Если куратор нажал «Не подходит», бот просит студента
   прислать другое фото на то же место.
5. После последней точки основного маршрута бот присылает сообщение
   «Вы завершили квест, молодцы!..» с кнопками **«🏁 Закончить квест»** и
   **«🔥 Еще места для самых смелых»**.
6. Если выбраны «Еще места» — бот по очереди присылает точки из
   дополнительного сектора (Section 4 в `coordinates.txt`). После
   последней из них бот присылает «Молодец!».

Кнопка «Техническая поддержка» — это ссылка прямо на профиль куратора
текущего сектора (`t.me/username`), не требует участия бота.

### Важное отступление от исходного описания

В задании куратор должен был подтверждать фото текстовым сообщением
«подходит». Я заменил это на кнопки **«✅ Подходит» / «❌ Не подходит»**
под самим пересланным фото. Причина: если у куратора одновременно
несколько фото на проверке (а на реальном квесте так и будет), текстовое
«подходит» не говорит боту, к какому именно фото оно относится. Кнопка,
привязанная к конкретной заявке, снимает эту неоднозначность и не требует
от куратора ничего печатать.

## Структура проекта

```
akadem_tg/
├── bot.py            # точка входа, все обработчики сообщений/кнопок
├── config.py          # токен, менеджеры секторов, пути к файлам
├── db.py               # работа с SQLite (прогресс студентов, заявки на фото)
├── coordinates.py      # парсер coordinates.txt
├── keyboards.py         # генерация inline-кнопок
├── texts.py              # все тексты на русском в одном месте
├── coordinates.txt        # ваш файл с точками по секторам
├── requirements.txt
├── .env.example
└── quest.db            # создаётся автоматически при первом запуске
```

Состояние каждого студента (маршрут, текущая точка, что от него сейчас
ждём) хранится в SQLite (`quest.db`), а не в памяти процесса — если бот
перезапустится посреди квеста, никто не потеряет прогресс.

## Запуск

### 1. Установка зависимостей

```bash
cd akadem_tg
python3 -m venv .venv
source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

### 2. Токен бота

Получите токен у [@BotFather](https://t.me/BotFather), затем:

```bash
cp .env.example .env
```

и впишите токен в `.env`:

```
BOT_TOKEN=123456:AAАшAбвгд...
```

Файл `.env` уже добавлен в `.gitignore` — токен никогда не попадёт в git.

### 3. Кураторы (менеджеры секторов)

Это самая важная часть настройки. Бот может писать пользователю в Telegram
только после того, как тот сам хотя бы раз написал боту (ограничение
Telegram, не мы придумали) — поэтому:

1. Каждый куратор должен открыть чат с ботом и отправить `/start`.
2. Каждый куратор отправляет боту команду `/id` — бот пришлёт его
   числовой Telegram id.
3. Откройте `config.py` и впишите эти id и `@username` кураторов в
   словарь `MANAGERS`:

```python
MANAGERS = {
    1: {"id": 111111111, "username": "ivanov_curator", "name": "Куратор сектора 1"},
    2: {"id": 222222222, "username": "petrova_curator", "name": "Куратор сектора 2"},
    3: {"id": 333333333, "username": "sidorov_curator", "name": "Куратор сектора 3"},
    4: {"id": 333333333, "username": "sidorov_curator", "name": "Куратор доп. точек"},
}
```

Сектор `4` — это дополнительные («для самых смелых») точки; по умолчанию
их проверяет куратор сектора 3, но это можно поменять на отдельного
человека.

Пока в `config.py` стоят условные `id: 1, 2, 3` — бот запустится, но
при старте выведет предупреждение в лог, что это заглушки и их нужно
заменить перед реальным квестом.

### 4. Файл координат

`coordinates.txt` уже лежит в проекте и разбит на секции:

```
[Section 1 -- Пирогова]
54.836009, 83.10096 ДУ
...
[Section 2 -- Морской проспект]
...
[Section 3 -- Щ]
...
[Section 4 -- дополнительно]
...
```

Секции 1-3 — основной маршрут (студенты комбинируют их порядок как
1-2-3, 2-1-3 и т.д.). Секция 4 — бонусные точки. Название точки
(«ДУ», «больница» и т.п.) видит только куратор в подписи к фото — самому
студенту бот присылает только координаты и ссылку на карту, чтобы не
подсказывать место.

Если нужно добавить/убрать точки — просто отредактируйте `coordinates.txt`
в том же формате и перезапустите бота.

### 5. Запуск

```bash
python3 bot.py
```

Бот будет опрашивать Telegram (long polling) — отдельный сервер с
вебхуком не нужен. Для боевого использования держите процесс через
`systemd`, `tmux`/`screen` или `pm2`, чтобы он не остановился при
закрытии терминала.

## Полезные команды бота

| Команда | Кто использует | Что делает |
|---|---|---|
| `/start` | студент | начать квест, выбрать маршрут |
| `/reset` | студент | сбросить прогресс и начать заново (полезно для тестов) |
| `/id` | кто угодно | узнать свой числовой Telegram id (нужно для `MANAGERS`) |
| `/stats` | админ (см. ниже) | сводка: сколько студентов начали/закончили, сколько фото ждут проверки |

Чтобы `/stats` заработал, впишите свой Telegram id (узнать через `/id`) в
`ADMIN_IDS` в `config.py`:

```python
ADMIN_IDS = {123456789}
```

## Тестирование перед реальным квестом

1. Пропишите себя куратором всех секторов в `MANAGERS` и запустите
   `/reset`, чтобы пройти квест самому от начала до конца.
2. Проверьте, что кнопка «Техническая поддержка» открывает нужный профиль.
3. Проверьте отклонение фото («❌ Не подходит») — бот должен попросить
   новое фото на то же место, не пропуская его.
4. Проверьте ветку «Еще места для самых смелых» и финальное «Молодец!».
5. Только после этого впишите реальных кураторов и запускайте на боевом
   токене.

## Возможные доработки на будущее (не реализовано, чтобы не усложнять MVP)

- Несколько кураторов на один сектор (сейчас — ровно один; в коде это
  легко расширить до списка).
- Ограничение по времени на точку / антифрод-проверки фото (сейчас —
  всё решает человек).
- Экспорт статистики в Excel/Google Sheets.
